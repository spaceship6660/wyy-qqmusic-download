## 手工验收清单（建议）

1. 登录 QQ / 网易云后，侧栏各出现「· 日推」。
2. QQ 日推总览 4 张卡都有封面、数量与更新时间；点「日推30首」能看到 30 首。
3. 点「下载全部（30 首）」→ 下载目录出现 `Q音<当天>日推30首/曲名.mp3`（文件名不加序号），无 `cover.jpg`、无 `album.cue`。
4. 在日推歌曲页勾选 2 首 →「下载选中」→ 两首平铺到下载根目录（与专辑页行为一致）。
5. 网易云日推总览 3 张卡；风格推荐页显示当前曲风；私人雷达页 35 首可打开。
6. 次日再开日推：列表与目录日期应为新一天；QQ 每日30首不应显示昨天的卡片。
7. 同一天重复下载同一入口：文件应带 `(1)`，不覆盖已有文件。

## 已知边界

- 网易云日推数量浮动（本机今日 34 首），按接口实值显示，不截断到 30。
- 网易云日推 6:00 更新；6:00 前打开可能仍是前一天列表，接口无可靠日期字段。
- 网易云风格推荐只读当前曲风；切换曲风会写账号偏好，本版不做。
- 日推批次不写 cover.jpg / album.cue / TRCK / TPOS；如需封面或 cue，需要另开需求。
- 日推入口只在登录后显示，与其它登录后子项一致。

## 0.8.1 修复：日推目录所有文件都是 01

- 现象：整批下载后 `网易云26-10-31日推30首` 里的文件全部以 `01 ` 开头。
- 根因：日推 `TrackDTO`（`neteaseTrackToDto` / QQ `dissSongToTrack`）没有 `trackNo`；`runDownloadJob` 用 `trackNo ?? 1` 拼 `NN 曲名`，整批都落到 1。
- 修复：`enqueue` 对 `album.kind === 'playlist'` 的批次按去重后的入队顺序补 `trackNo = 1..N`、`disc = 1`，再交给下载管线；专辑批次行为不变。
- 回归：`tests/app.test.ts` 新增 QQ / 网易云两条用例，曲目不带 `trackNo` 时落盘为 `01 t1.mp3` / `02 t2.mp3`。
- 旧产物：0.8.0 生成的 `01 ...` 文件不会自动改名；删掉旧目录用 0.8.1 重下即可。

## 后续调整：日推批次文件名不再加序号（2026-11-03）

- 需求：日推整批下载的文件名去掉 `NN ` 前缀，直接用曲名。
- 实现：`runDownloadJob` 对 `album.kind === 'playlist'` 使用 `safeName(曲名)`；普通专辑仍按曲序命名（`NN 曲名.ext`），
  cue/标签行为不变。入队时也不再为日推曲目补 `trackNo`。
- 回归：`tests/app.test.ts` 两条日推落盘用例改为断言 `t1.mp3` / `t2.mp3`。
- 旧产物：已下过的 `01 ...` 文件不会自动改名，需要的话手动重命名或删掉重下。
