# 音乐下载器（QQ 音乐 + 网易云）

一个对标 [Creamplayer](https://github.com/Beadd/Creamplayer) 的桌面音乐下载器（Electron + TypeScript 单语言实现）：搜索 / 歌单 / 登录后无损下载，自动内嵌封面与中日对照歌词，标签规格面向 **foobar2000** 与 **Musicolet**。

> 本项目从调研到实现全流程记录在 `docs/`（specs / plans / 验收 / 调研），详见文末「文档索引」。

## 功能

### 找歌：搜索

- **双平台音源**：QQ 音乐 + 网易云，歌曲 / 专辑双 tab，关键词搜索 + 单曲/歌单/专辑链接导入。
- **结果内联展示**：搜完直接铺在搜索页下方，歌曲/专辑 tab 常驻；切 tab 有关键词时自动按当前 tab 重搜，不用再按一次搜索。
- **专辑**：点卡片进专辑歌曲页，返回回到专辑列表（QQ 专辑封面为完整直链；网易云专辑内联展开）。

### 拿歌单：登录后左侧导航

- **QQ 音乐**：我喜欢的音乐（dirid=201）/ 自建歌单 / 收藏的歌单。扫码登录（ptlogin2）同时保存 EncryptUin（收藏歌单接口必需）；手动导入的 Cookie 没有它，收藏页会明确提示退出重扫。
- **网易云**：我喜欢的音乐（specialType=5 置顶）/ 自建 / 收藏，歌单卡片带封面。
- **退出登录**：左下两行登录态各带退出按钮，退出清对应缓存并收起导航。

### 下歌：质量与队列

- **质量档位**：无损（flac）/ APE / 320k / 128k / m4a（QQ）；网易云侧只给 无损 / 320k / 128k（APE 与 m4a 在该平台没有对应 br 档，v0.7.0 起不再摆出来）。拿不到自动降级，「我的下载」里黄条提示（进行中与已完成都显示），文案点名实际落到的档（「已降级为 320k」）。**网易云侧的降级判定 v0.7.0 修**：此前选 APE/m4a 因无对应档而**恒**挂「已降级」、且不发无损请求（直接 320k 起跳）；现在这两档按无损起跳，「已降级」只在交付档真低于目标档时出现（拿到无损就不挂）。APE/m4a 无标签写入器，可正常下载但**不内嵌封面/歌词**（按歌词档只另存 `.lrc`）。
- **降级按「该曲实际登记的档位」做**（v0.6.0 修）：QQ 直链接口**只按候选列表首位核发**，首位档位不存在就整批回空、不逐条回退——所以下载前先取该曲详情，把候选收窄到它真实存在的档位（无损 → APE → 320k → 128k → m4a）。只登记 128k 的曲子会直接降到 128k 下载成功，而不是「无损拿不到就整首失败」。详情取不到时退回全档尝试（网易云侧本就是逐档单独请求，不受此影响）。
- **失败原因说人话**（v0.6.0 修）：QQ 拿不到直链时报错会回显该曲登记的档位，并区分「会员/付费曲权益不足」与「服务端未提供任何档位直链（多因版权方未开放下载）」，不再是「可能需要登录」这类不携带信息的通用文案。
- **下载身份（两源可单独设）**：登录账户 / 匿名二选一，只影响下载直链用的凭证（歌单浏览仍用登录态）。个别账号登录态反而拿不到直链时切匿名试试；匿名拿不到无损。设置页改，即时生效。
- **直链被 CDN 节点拒收时先换节点**（v0.6.1 修）：网易云账号态直链常被分配到 `m704/m804` 这两个**恒定 403** 的 CDN 节点（签名、权益、会员都正常，换节点立即 206），旧逻辑一遇 403 就改走匿名，于是**每一首都显示「已切匿名下载」**、并因匿名拿不到无损而顺带降级。现在遇 403 先做**同 URL 换节点重试**（`m701/m801/m802`，路径与签名参数一字不改），保住账号身份与无损档；全部节点都失败才走匿名兜底。
- **本批选项**：码率 + 歌词模式选择条在 QQ / 网易云的搜索页与**所有歌曲列表页**（含专辑歌曲页）顶部**吸顶显示**，翻多长都看得见；改动即存为默认值，下次打开接着用。**v0.7.0 修**：此前切到「专辑」tab 时整条选择条消失，专辑路径全程只能吃设置默认值，现已常驻。档位列表**按来源过滤**（网易云只给 无损/320k/128k），当前档位不在本源可见档内时挂载即改判无损并落盘——副作用见「已知限制」。
- **下载不跳页**：点「下载选中」后留在当前列表继续勾选；左上弹出下载浮卡（曲名 + 进度，可收起），点标题进我的下载。「下载整张」同样不跳页。
- **我的下载**：顶部 tab 分类（全部 / 下载中 / 已完成 / 错误）；失败行有**重试**按钮，按原参数重跑（整张专辑的任务也带着专辑上下文重试，不会掉回平铺根）。
- **下载管线**：并发队列（可调 1-4）、下载侧 1 请求/秒限速、`.part` 原子写、同名占位防碰撞、直链过期自动重取一次。
- **失败可查**：全档拿不到直链时队列显示服务端原文因；vkey 失败现场（每档有无，不记密钥）写入本地诊断日志。

### 整张专辑下载（标准专辑封装）

- **入口**：QQ / 网易云专辑歌曲页头部「下载整张（N 首）」按钮，与底部「下载选中」并存（不替换它）。点它**忽略当前勾选**，把本页全部曲目连同专辑批次上下文整批入队，档位/歌词仍走上方选择条的当前值。本页曲目数少于这张专辑的真实曲目数时，按钮写成「下载整张（已加载 x / y 首）」，点击先弹确认说明后果。
- **产物形态**：`下载目录/歌手 - 专辑 (年)/01 曲名.flac …` + `cover.jpg` + `album.cue`；封面按图像魔数命名（嗅探到 PNG 就落 `cover.png`，不让它冒充 `.jpg`），抓不到就跳过并写一行诊断日志——封面是附属品，不因为它拿不到就把已下好的歌判成失败。多碟专辑每碟一个 `CDnn/` 子目录，**每碟各一份 `album.cue` 写在自己碟目录里**，`cover.jpg` 只在专辑根一份（不在每个 CDnn 里重复）。碟号不进 cue 文本——目录就是碟号的载体。
- **只有整张才进专辑目录**：在专辑页手动勾选部分曲目、走「下载选中」，产物仍是原来的平铺文件（路径、命名、标签与 0.6.1 一致，不写 TRCK/TPOS，也不产生任何附属文件）。
- **标签**：专辑模式下额外写曲目/碟序号——MP3 `TRCK`（`序号/总数`）+ `TPOS`，FLAC `TRACKNUMBER` / `TRACKTOTAL` / `DISCNUMBER` / `DISCTOTAL`。总数取**专辑实长**而不是这批入队了几首（共 10 首只下 2 首时标签写「1/10」）；碟总数只在多碟时写，单碟不凭空造出「这专辑共分一碟」。
- **cue**：UTF-8 with BOM + CRLF（无 BOM 时 foobar2000 在中文 Windows 按 GBK 猜，中文曲名乱码）。每曲一个 `FILE` 段、一个 `TRACK`，`INDEX 00 00:00:00`（每曲一文件形态，不是整轨 image 的分轨偏移）；`FILE` 的容器关键字与文件名都取自**实际落盘的那一笔**——降级导致一张专辑 flac/mp3 混排、或同名冲突被加过 `(1)`，cue 都不会指向不存在的文件。
- **cue 只在整碟真地下齐时写**：完成度判据是**这张专辑该碟的真实曲目数**（`AlbumBundle.discTotals`，由解析层从完整曲目数组算出），不是你这批入队了几首。半张的 cue 会把这张 10 首专辑在播放器里呈成 2 首，比没有 cue 更糟，所以宁可没有。失败行照常「重试」，重试成功后整碟 cue 全量重写；某碟一旦齐了，之后覆写落盘名也会跟着重写 cue。

### 歌词与标签

- **中文译文自动合并**：网易云 `tlyric` + QQ（`trans:1` 参数）译文按**时间戳**配对，插到原文行下中日对照；作词/作曲头行不动，QQ 的 `//` 占位行与注音标签自动丢弃。源头没有译文的歌保持原文（QQ 译文覆盖本就少于网易云）。
- **歌词四档**：内嵌+另存 .lrc / 仅内嵌 / 仅另存（不内嵌）/ 不保存（不取歌词）。
- **播放器兼容**：封面必内嵌（MP3=APIC / FLAC=PICTURE）；MP3 写 ID3v2.3 USLT+SYLT 双帧，FLAC/OGG 写 Vorbis `LYRICS`+`UNSYNCEDLYRICS` 双键——foobar2000 装 ESLyric 等任意歌词组件即可显示，Musicolet 原生读取。

### 浏览体验：缓存

- **秒开**：我喜欢 / 歌单 / 专辑歌曲页 session 级内存缓存，切走再回零等待；翻页进度写穿进缓存。
- **后台追新（SWR）**：命中缓存先渲染旧数据，后台只拉首屏做 diff，有变化才原地替换（勾选交集保留），标题旁小字提示「正在检查更新… / 已是最新 / 已更新」；60 秒新鲜度窗口内零请求，无感且防风控。
- **手动刷新**：标题旁 `↻ 刷新` 按钮随时强制重拉；失败（风控/断网）静默保留旧缓存。
- **加载态**：切页瞬间同步占位 + 居中转圈遮罩 + 回到顶部；快速连点时慢响应自动丢弃，不会旧页面盖住新页面。

### 解密

- 导入 QQ 音乐加密文件（.mflac/.mflac0/.mgg/.mgg0/.mgg1/.qmc0）→ 还原原容器（flac/ogg/mp3）；文件名「歌手 - 歌名」搜索匹配后自动补封面/歌词/标签；musicex 等无密钥格式明确报错。

## 快速开始

```bash
# 开发运行（Electron 二进制下载需代理时加 HTTPS_PROXY）
npm install
npm run dev

# 打包 Windows 安装包（electron-builder，产出 dist/）
npm run dist

# 类型检查与测试
npm run typecheck
npx vitest run
```

**使用流程**

1. **QQ 音乐 / 网易云**：搜索框输入歌名/歌手（歌曲/专辑 tab 随时切，自动重搜）+ 粘贴单曲/歌单/专辑链接；结果勾选后点**窗口底部固定下载栏**「下载选中」，留在本页继续挑。
2. **歌单**（登录后左侧导航出现次级项）：我喜欢的音乐 / 自建歌单 / 收藏的歌单 → 歌单列表 → 点开 → 歌曲列表；超长歌单滚动到底自动续拉（1500+ 首也不会一次全拉）；标题旁 `↻` 可强制刷新。
3. **解密 Tab**：选文件或整个文件夹（自动过滤加密扩展名）→「解密并补全」→ 结果列表 ✓ 已补全 / ○ 仅解密 / ✗ 失败原因；输出目录在设置页可改。
4. **设置**：默认码率、并发数、下载目录、解密输出目录、歌词模式。

## 风控与已知限制（如实说明）

- **能播≠能下**：播放（流媒体）与下载是两套权益。部分同人/OST/数字单曲 App 里能播，但服务端全档不给下载直链——此时失败是正确的，队列会显示原因。
- **限速范围**：1 请求/秒限速目前只覆盖**下载管线**；浏览请求（搜索/歌单/翻页）不限速，靠 60 秒缓存新鲜度窗口压请求量。短时间内连点三四个不同歌单仍可能撞网易云频控（空响应，冷却 20~60 秒），等半分钟按 `↻` 重试即可；QQ 宽松得多。
- **QQ 匿名下载已被服务端收紧**：匿名 `CgiGetVkey` 返回空 purl，免费歌也要登录态。
- **网易云匿名**：普通歌 320k/128k 可下；个别版权歌匿名 404 需登录；无损需登录+账号权益，无权益自动降级。**匿名即使请求无损档也只回 320k**（实测），所以无损必须保住账号身份。
- **网易云无损档参数**（v0.6.1 修）：该端点拿无损必须用 `br=999000`，写 `0`（旧实现）恒返回 `code:200 / url:null`——**即便账号是有效会员也一样**，于是无损请求必然落空、每首都降级到 320k，还白打一次废请求。
- **网易云 CDN 节点**（v0.6.1 修）：账号态直链被发到 `m704/m804` 时这两个节点对该签名直链**恒定 403**（与请求头、http/https 均无关，重取直链仍是同一节点），而同一串 URL 换 `m701/m801/m802` 立即 206 且内容为真 FLAC。这是**节点级拒收**，不是账号被限制，更不是会员失效。
- **QQ 译文覆盖**：少于网易云；源头没有译文的歌只写原文。已下载的旧文件不会自动补译文，删了重下即可（同名自动加后缀不覆盖）。
- **QQ 登录会过期，且「已登录」不等于会话有效**：浏览类接口（歌单 / 我喜欢）靠账号标识 `EncryptUin` 鉴权，**会话密钥 `qqmusic_key` 过期后照样能取数**，但下载直链按密钥核发——此时全档空 purl、什么歌都下不了（免费曲也一样）。下载失败会自动调**凭证校验接口**（`music.UserInfo.userInfoServer / GetLoginUserInfo`，过期码 `1000`/`104400`/`104401`）探活：确认过期 → 左下角显示「登录已过期 · 重新登录」，点一下重扫码即可；仅当凭证确实有效才保留「无版权 / 权益不足」语义，不再把过期当成「没版权」误导。
- **失败点名会员/付费**：拿不到直链时，带 VIP / 付费标记的曲子会被点名为权益问题（需绿钻 / 豪华绿钻或单独购买），普通歌才走通用文案。QQ 的 VIP 判定取 `pay.pay_down`（歌单 / 我喜欢条目带完整 pay 对象）或详情里的 `flags.try_begin`，因此歌单 / 我喜欢来源也会显示 VIP 角标。**注意不能用 `file.try_begin`**：免费曲也带该字段（实测一首 pay 全 0、只登记 128k 的曲子带 `file.try_begin=95604`），拿它判 VIP 会把免费曲误报成会员歌。
- **QQ 不下载 ogg 档**：部分曲子（同人上传居多）服务端只登记 128k mp3 / 48k·96k aac / 192k ogg。前两者可下；ogg（`O400`/`O600`）音质更高但无标签写入器，当前不进候选链，故这类曲子会落在 128k mp3 上。要下 ogg 需先补 ogg 标签支持。
- node-id3 写 MP3 为 ID3v2.3 + UTF-16（foobar2000/Musicolet 均原生支持；个别古董设备可能不识别）。
- 解密：musicex（"cex\0" 结尾）与 STag 无内嵌密钥（密钥在 Mac/Android 的 MMKV），Windows 侧明确报错；OGG 等容器暂不补标签（只解密）。
- **整张专辑的 cue 按「这张专辑有几首」判齐，不按你入队了几首**：完成度取 `AlbumBundle.discTotals`（解析层从完整曲目数组算出的该碟真实曲目数）。因此「本页曲目少于专辑实长」的那一批（残缺批次）只有音频与 cover、**没有 cue**。渲染侧不许假装下完了整张：按钮文案变成「下载整张（已加载 x / y 首）」，点击先弹确认（写明这批不会有 cue），入队后的回显再说一遍。恢复：把剩余曲目加载完再点一次「下载整张」——本页全部已加载曲目会一起重新入队，已下过的**不覆盖**，由 `uniquePath` 多落一份 `01 曲名(1).flac`，cue 于是收最新那一笔账（`tests/app.test.ts` 两条用例锁住这条路径）。**注意**：当前两侧专辑页都是单响应给出全部曲目（专辑页不挂「加载更多」游标，`App.vue` 的 `openAlbum` / `NeteaseTab.vue` 的 `openAlbum` 都不带 cursor），所以这条残缺路径在正常专辑流程里走不到，它是防「服务端只回部分曲目 / 共享列表被别的来源改短」的守卫——能否在真实专辑页复现见 `docs/acceptance-album.md` 的开放项。
- **QQ 专辑曲目序号取列表下标**：`fcg_v8_album_info_cp.fcg` 的条目里**没有**序号字段（实测只有 `belongCD` / `cdIdx`，`track`/`seq` 均不存在），故 `trackNo = 下标 + 1`。网易云侧有权威的 `songs[].no`（缺失才回退下标+1）与 `songs[].cd`（实测 `'01'` 这种字符串）。
- **QQ 专辑 `total_song_num` 与 `list.length` 口径不一致**（实测同一张 21 vs 22）：一律以实长为准——`AlbumBundle.totalTracks` 就是曲目数组长度，cue 的判齐、序号位数（≥100 首转三位）、TRCK/TRACKNUMBER 的总数都跟着实长，不信服务端计数。
- **QQ 多碟判定未经真实多碟样本验证**（spec 风险 R1）：`cdIdx` 字段存在已确认，但取值语义从未拿一张真实多碟专辑核对过，认不出（不是 ≥1 的整数）一律按单碟处理。最坏情况是多碟专辑被拍平成一个目录、序号连续——丢结构，不出错。完成度按 `(碟号, 曲序)` 记账，所以「每碟从 1 重新编号」这种通行发行形态不会让两碟的第 1 首互相顶掉槽位（按 trackNo 单键记账时两碟都永远配不齐）。
- **APE/m4a 整张不出 cue**：这两个容器没有标签写入器，cue 依赖的 track 号根本写不进去，所以那一碟直接跳过 cue——宁缺不错，不给播放器一份它索引不了的 cue。曲目照常下载、cover 照常写。网易云侧走不到这条（该源只会落 flac/mp3）。
- **专辑元数据零额外请求，但两侧的封面来路不同**：网易云 `album` 级字段与 `songs[]` 在同一次 `/api/v1/album/{id}` 响应里，专辑对象键名是 **`album`** 不是 `info`（认错键名等于什么都没接到，有反锚用例）。QQ 侧 `data` 里 `name/singername/aDate/company/mid` 齐备，但**响应内没有封面字段**，`cover.jpg` 的大图 URL 只能由 albummid 拼 `T002R500x500M000<mid>.jpg`（2026-10-07 真实网络复核：HTTP 200、63,584 字节、魔数 `ffd8ff`；曲目自带的 R300 做封面图太小）。
- **网易云页不再提供 APE/m4a，并且会改写持久化的默认档位**：选择条按来源过滤，挂载或切源时若当前档位不在本源可见档内，立即改判无损**并 `settings:set` 落盘**。后果：默认档位是 APE 的用户第一次切到网易云 tab，这个默认就被改成了无损（要回 QQ 用 APE 得重选一回）。相关毛刺如实记录：**设置页仍然无条件列五档**（`SettingsPanel.vue`），以网易云为主的用户还能在那里选 APE，然后在下一次进网易云页时被静默改写——设置页的按源过滤是遗留项，本版没做。
- **网易云「登录已失效」要求服务端确实拒绝凭证**：只有 `/api/nuser/account/get` 回来不带 `profile.userId` 才判失效；断网或被频控时探测**上抛**，此时保守沿用 cookie 文件判据、不再谎称过期（此前 `neAccount` 把所有异常吞成 null，网络抖动一律显示「登录已失效」，把用户赶去重扫码）。探测结果缓存 60 秒，且与 `ne:account` 共用同一次探测（一个窗口一次请求、一个结论，侧栏与页头不再各读一半打架）。副作用：会话中途失效会在缓存过期后的下一次调用（进网易云页 / 点侧栏歌单）才暴露，不是立刻。导入 / 退出 / 窗口保存登录态时清缓存。

## 技术栈与结构

- Electron 36 / electron-vite / Vue 3 + Pinia / TypeScript / Vitest / node-id3 / music-metadata（测试读回验证）

- 渲染器：`stores/`（含列表来源标记防串台下载）+ `qualityOptions.ts`（档位表按源过滤 + 落档中文名，词表只此一份）+ `components/`（搜索/网格/队列/登录/设置/网易云/解密 Tab）
- 测试：`tests/`（28 个文件 / 379 用例全绿：client/数据层/直链/凭证校验/登录/队列/标签/歌词合并/CDN 节点规则/专辑命名/专辑封装与完成度/app 集成/renderer store/unlock 向量，全部 mock 或本地 server；真实网络仅手工验收）

## 隐私与合规

- 登录凭证（QQ/网易云 cookie）明文存于用户数据目录（`userData/qqmusic_cookie.json`、`netease_cookie.json`），仅本机使用，不入库、不打印、不上传。
